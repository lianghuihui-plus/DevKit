# MAVT MCP 优化设计

用户于 2026-10-22 批准在独立 worktree 实施此前列出的八项优化，要求功能和性能不劣化；代码与离线能力验证由开发侧完成，手机设备验收由用户完成。不得自动安装插件，不合并、不推送。

## 不变的执行语义

- Node.js 现有运行时、平台 Adapter、事务、证据、Case Flow、报告为唯一实现；MCP 通过同一应用服务调用，不复制业务逻辑。只保留一个 MCP 插件版本，移除新流程中的 CLI 备选分支；仍被共享业务实现、Loader、维护或离线验证使用的脚本保留。
- READY / 非空目录保护、显式初始化、知识 prepare/apply、UNKNOWN 不重放、独立 Case Agent、单写入者、dispatch sequence、不可变引用和固定版本继续生效。
- 新工具层必须验证输入并在错误路径中保留领域错误；MCP 成功送达不等于业务成功。只读查询不推进状态、不写遥测、不修复、不探测设备。
- 不创建常驻后台测试引擎，不自动发现并导入其他宿主工具，不添加 Hooks 自动推进测试。

## 架构与绑定

`0.2.1` 统一构建一个本地 stdio MCP 插件，始终发布完整闭包及 `mcpServers` 注册，不再提供普通版/预览版开关。构建生成固定的 `mcp-transport.json`，新 Handoff 将 MCP 选择冻结到 Brief，公开 `caseDispatch.transport`，并移除 Brief 中未使用的 CLI 命令与 shell 模板。入口只负责协议、工具发现与路由；管理服务位于可固定的 runtime 内。工具 Schema 从权威契约生成，输出结构 Schema 与实际结果一致。大型 JSON 不在 text 与 structuredContent 中重复返回；错误结果保留状态、错误码和 UNKNOWN 信息。

管理工具覆盖工作区显式打开/初始化、只读诊断、用例结构化导入、知识查看/校验/prepare/apply、Run 创建/确认/推进/取消、只读状态/报告。参数使用绝对工作区路径或服务生成的不透明绑定引用，不能依赖进程内的 mutable currentWorkspace/currentRun/currentExecution。绑定按角色、bundle 和作用域校验；知识维护计划还要校验运行时代码身份。

Case 工具通过固定 Loader 领取当前 handoff 后取得 execution/dispatch 绑定，正常调用不接收裸 executionId、进程环境或任意执行路径。每次调用重新验证固定版本与活动 sequence，旧/替换 dispatch 立即失效；共享服务的引用隔离不宣称 OS 沙箱或已识别宿主调用者身份。若宿主不支持每子 Agent 动态配置 MCP，可使用显式绑定引用路由，保持职责隔离；工具可见性与上下文隔离分别验证。

已有旧 bundle 不补写、迁移或降级到新实现；支持 MCP 的旧 Run 继续路由到其原固定副本。缺少 MCP 接口的在途任务报告接口不兼容，由原版本处理，当前插件不再提供 CLI 分流。三个 Skill 的新任务均直接使用 MCP，不要求额外试用授权；Case Agent 原样执行一次 Loader，再使用返回的 execution/dispatch contextRef 调用 Case 工具。

截图通过已校验资源生成 MCP image 内容，采用显式按需读取，避免每个 observe 强制附大图造成带宽和上下文退化。图片与 scene/ref/摘要绑定，送达不自动登记 inspect，不取代证据规则。其他资源继续按需 read；MCP Resources 支持不作为宿主的必要前提。

Harness 能力契约必须反映实际能力，区分静态本地支持与会话内独立上下文、图片、Agent 句柄、等待和取消的运行时检查。没有可靠能力时明确阻塞，不能在父 Agent 内代执行 Case。

每个 MCP 服务实例维护共享 worker 池，最多 5 个 worker，按工具调用分配并复用，不绑定批次或 Case Agent。默认空闲回收时间由 30 秒延长为 5 分钟，空闲期间再次调用会重新计时；执行中的操作不受此空闲期限影响，服务关闭时仍主动释放空闲 worker。此调整减少思考和设备操作间隔中的重复启动，但会延长空闲进程的内存保留时间，不能保证一个 Case Agent 生命周期内只发生一次 worker 启动。历史性能与 RSS 数据是在原 30 秒策略下测得，不能作为新策略的整批实测结果。

## 验收与性能

先运行原始完整回归作为功能基线。新增协议进程测试、真实运行时管理生命周期、多个工作区/Run 交错、跨角色/跨 scope、旧版本恢复、失效 dispatch、未知动作、知识版本/内容失效、资源完整性与图片字节测试。MCP 请求不额外启动每操作 CLI 子进程；固定代码和真实文件校验不能因缓存被跳过。

可复现离线 benchmark 比较原 CLI、当前共享实现的直接调用及同一 MCP 构建的工具调用，记录冷 Loader/首读和暖调用 p50/p95、字节、进程数与 RSS，不再构建第二个分发版本。历史 0.2.0 的 30 暖/12 冷样本显示暖 MCP 五类操作更快，冷 Case MCP 266/274 ms 慢于原 CLI 174/184 ms；历史严格冷暖对等门槛仍记为失败，不改写为通过。用户接受该冷启动取舍并选择仅保留 MCP，0.2.1 不是一次新的整批性能实测。基准的严格比较与产品选择分开表述，当前不再用名为“默认切换批准”的指标代替用户决策。
