# MAVT 知识文件契约

## 文件结构

每个 `.md` 文件只包含一个条目，第一行格式为：

```markdown
# K-<stable-id> <title>
```

随后必须严格按照以下顺序包含四个非空章节，不能新增其他二级章节：

1. `## 适用范围`
2. `## 可观察现象`
3. `## 结论与处理建议`
4. `## 追溯信息`

单个文件不能超过 512 KiB。知识目录不允许符号链接；条目 ID 在整个 Workspace 知识目录中必须唯一。

## 适用范围字段

字段使用 `- Field: value`，多值使用英文逗号分隔。

| 字段 | 规则 |
|---|---|
| `App` | Android/HarmonyOS 包名或 iOS Bundle ID，不能写产品展示名 |
| `Platform` | 只能是 `harmony`、`android`、`ios` |
| `Version` | 精确数字版本、末段 `x/*`，或数字版本范围 |
| `Page` | 知识实际适用的业务页面 |
| `Operation` | 触发现象的业务操作 |
| `Valid until` | `YYYY-MM-DD`；过期条目仍存在，但不能作为适用知识 |
| `Conflicts with` | 已存在且不是自身的 `K-` ID |

未知字段事实必须省略，不能为了“完整”猜测。省略表示该维度不限制适用范围；写错则可能导致 MAVT 查询直接排除该条目。

## 内容职责

- `可观察现象`：当前截图、控件树或业务现场可以核对的事实。
- `结论与处理建议`：已确认解释、适用边界和处理办法。
- `追溯信息`：来源、确认人或确认方式，以及 `YYYY-MM-DD` 日期。

`UPDATE` 不能改变条目 ID。变更 ID 必须由用户明确授权为删除旧条目并新增新条目。
