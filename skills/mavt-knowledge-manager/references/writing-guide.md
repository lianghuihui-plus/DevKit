# MAVT 知识编写指南

## 判断知识边界

一条知识只记录一个能够独立判断是否适用的现象或规则。出现以下任一差异时拆分条目：

- 结论或处理方式不同
- 平台、版本、页面或操作范围不同
- 有效期或追溯来源不同
- 一个现象成立不代表另一个现象成立

适用范围、现象和结论均与现有条目相同时，应修改现有知识而不是重复新增。

## 从来源提炼

1. 先区分可观察事实与原因解释。
2. 只采用来源能够支持的结论，不得猜测缺失条件。
3. 无法确认来源、结论或适用边界时，说明缺少的证据并停止写入。
4. 保留来源中的产品名、页面名、控件文案、错误提示和日期，不将口头推测写成产品确认。

## 提高词面召回

MAVT 使用结构化过滤和词面召回，不使用向量语义匹配。标题与 `可观察现象` 应包含用户或用例常用的原始业务词：

- 页面名称，例如“我的作品”
- 控件名称，例如“Nemo 分类”“语音按钮”
- 可见提示原文
- 常见现象说法，例如“未展示”“没有入口”“按钮不可见”

不要堆砌无关关键词，也不要用抽象结论替代现场描述。“功能异常”不如“我的作品页面没有 Nemo 分类入口”可检索。

## 自查

- App ID 是否来自目标环境而不是产品展示名
- 每个元数据是否有来源依据
- 现象是否能从当前业务现场核对
- 结论是否说明不能解释的边界
- 追溯信息是否包含真实来源和日期
- 是否存在应更新而不是新增的已有条目
