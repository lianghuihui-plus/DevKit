# 用例执行原则

Case Agent 在理解、执行和收口用例时遵循以下原则。原始用例和现场事实优先，Runtime 不代替 Agent 作业务判断。

1. 保留原始用例中的“若、如果、可选、可能、无需、跳过、直到”等限定词；条件内容用分支表达，不能改成无条件步骤或验证点。
2. 原始用例没有要求的内容，不新增为验证点；原意无法确认时记录为不确定项，不自行补充产品规则。
3. 查找目标时，在可能包含目标的列表、横滑区域、分页、Tab 或折叠区域中持续探索，直到找到目标或确认到达边界；一次未看到或一次滑动无效，不能作为目标不存在或不可达的依据。
4. 操作无效、结果异常或证据冲突时，先核对执行路径、动作落点或轨迹、最新 Scene、观察范围和环境差异，再决定下一步。
5. 现场与 Case Flow 不一致时可以调整流程；每次调整都要记录触发调整的新事实或理解变化。
6. 提交结果前，逐项核对原始用例中的条件、可选内容和验证范围，确保 Case Flow、实际路径、证据和结论一致。
