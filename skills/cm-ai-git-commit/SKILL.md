# CodeMao AI 代码提交

扫描代码仓库未提交变更，根据当前上下文推断提交范围，询问 TAPD 链接，生成提交信息，经用户确认后提交。

## 触发边界

仅在用户请求中出现以下明确意图时使用本 Skill：

- 用户明确说 `CodeMao AI 提交`、`CM AI 提交`、`AI 代码提交`、`按 CodeMao 提交规范提交`。
- 用户明确要求提交信息包含 TAPD 链接或 `[AI]` 格式。
- 用户提供 TAPD 链接并要求提交代码。

以下情况不要使用本 Skill，按普通 git 提交流程处理：

- 用户只说 `提交代码`、`帮我 commit`、`git commit`、`提交一下` 等普通提交请求。
- 用户没有提到 TAPD、`[AI]`、CodeMao/CM AI 提交规范。
- 用户只是询问 git 状态、查看 diff、暂存文件或生成普通 commit message。

## 定位代码仓库

先根据当前上下文推断 `REPO_PATH`，包括用户最近提到的路径、当前工作目录、打开文件所属目录、变更文件路径和本轮任务目标。

按以下优先级确定：

1. 用户明确提供了仓库路径 → 使用该路径。
2. 当前上下文能明确指向某个 git 仓库 → 使用该仓库。
3. 当前工作目录是 git 仓库 → 使用当前目录。
4. 仍无法判断 → 询问用户仓库路径。

验证 `REPO_PATH` 是 git 仓库：`git rev-parse --git-dir` 成功。否则终止。

## 执行流程

### 步骤 1：扫描变更和暂存区

在 `REPO_PATH` 下执行：

```bash
git status --porcelain
git diff --name-only
git diff --cached --name-only
```

无变更 → 告知用户并终止。

有变更 → 展示变更文件列表和当前暂存区文件列表，继续分析本次提交范围。

如果 `git diff --cached --name-only` 已存在暂存文件：

- 暂存文件属于本次提交范围 → 纳入提交前确认列表。
- 暂存文件不属于本次提交范围 → 停止并询问用户如何处理。
- 无法判断暂存文件是否属于本次提交范围 → 停止并询问用户。

未经用户确认，不得提交已有暂存区中的无关文件。

### 步骤 2：推断提交范围

根据当前上下文和变更内容推断本次相关文件，只 stage 相关文件。

推断依据：

- 用户本轮要求或刚完成的任务。
- 最近编辑、创建、删除的文件。
- `git status --porcelain` 中的变更文件。
- `git diff --name-only` 和 `git diff --cached --name-only` 中的文件。
- 相关文件的 diff 内容。
- 文件内容是否属于同一功能、修复、文档或重构。
- 变更之间是否存在直接依赖。

要求：

- 禁止默认使用 `git add -A` 或 `git add .`。
- 不提交明显无关文件。
- 不提交疑似敏感文件，例如 `.env`、密钥、证书、凭据文件。
- 不能只根据文件名推断提交内容；必须查看相关 diff 后再生成提交范围和提交描述。
- 如果提交范围无法从上下文可靠推断，应询问用户选择要提交的文件。

### 步骤 3：询问 TAPD 链接

向用户询问本次提交对应的 TAPD 链接：

```text
请提供本次提交对应的 TAPD 链接：
```

用户提供 TAPD 链接后继续生成提交信息。

### 步骤 4：生成提交信息

按固定格式生成提交信息：

```text
<TAPD链接>

[AI]
- Implemented: <描述，不超过 50 字>
- Affected modules: <模块名>
```

要求：

- `<TAPD链接>` 使用用户提供的原文。
- `Implemented` 概括本次实际完成内容，不超过 50 字。
- `Affected modules` 写受影响模块、目录或能力名称，避免堆砌完整文件列表。
- 不编造未发生的改动。

### 步骤 5：提交前确认

执行提交前，必须向用户展示：

- 推断出的 `REPO_PATH`
- 准备提交的文件列表
- 当前已暂存且会进入本次提交的文件列表
- 完整 commit message

用户确认后继续；用户拒绝则停止或按反馈修改提交范围/提交信息。

### 步骤 6：执行提交

1. 将确认后的提交信息写入临时文件。
2. 执行 `git add <file1> <file2> ...`，只添加确认范围内文件。
3. 再次执行 `git diff --cached --name-only`。
4. 核对暂存区文件列表与用户确认的提交文件列表一致。
5. 如不一致，停止提交并向用户说明差异；不得继续执行 `git commit`。
6. 一致后执行 `git commit -F <临时文件路径>`。
7. 删除临时文件。
8. 执行 `git log -1 --name-only`，核对最终提交文件与确认范围一致。

提交完成后告知用户：

- commit hash
- 当前分支名
- 本次提交文件数量

## 安全规则

- 不自动 push，除非用户明确要求。
- 不执行 `git reset --hard`、`git checkout --` 等破坏性命令。
- 不跳过 hooks，除非用户明确要求。
- 不修改 git config。
- 提交失败时，先报告失败原因，再根据错误处理。
- 未经用户确认提交文件和提交信息前，不得执行 `git commit`。
- 提交前暂存区文件列表与用户确认文件列表不一致时，不得执行 `git commit`。
